# ModBus协议

## 😃协议规定

1️⃣从机接收到数据的时候，`CRC错误`**直接丢弃**,不做任何响应
2️⃣如果报文`第0个字节`是`0x00`,说明是`广播模式`，此时消息发送给所有从机，**从机都不能响应**（不然会总线冲突）
注意：**广播只能是用于写操作，不能是读操作**
3️⃣**数据帧结束标志**：`3.5个字符`的时间没有接受到新数据，判断这一帧`数据结束`
4️⃣**最短帧长校验**：协议规定，一帧报文最短`不得少于4个字节`，如果小于4字节，**视为噪音，直接丢弃垃圾数据包**

  * 1字节从机地址
  * 1字节功能码
  * 0字节数据（允许为空）
  * 2字节CRC校验码

5️⃣**异常**响应格式：把功能码最高位置1

```c
tx[1] = func_code | 0x80;  // 功能码最高位置1
```

协议规定：当从机检测到错误时，响应的功能码必须把最高位（bit 7）置 1，主站正是通过这个标志位来区分正常的响应和异常响应。
例如：
• 正常响应功能码 0x03 → 异常响应功能码 0x83
• 正常响应功能码 0x06 → 异常响应功能码 0x86

6️⃣**异常码标准化处理**：

```c
typedef enum {
    EX_ILLEGAL_FUNC   = 0x01,   // 不支持的功能码
    EX_ILLEGAL_ADDR   = 0x02,   // 地址越界
    EX_ILLEGAL_VALUE  = 0x03,   // 数据值非法
} ModbusExceptionCode;
```

协议规定：Modbus 协议预定义了一组标准的异常码，其中最常见的三个就是：
• 01：非法功能码（从机不支持这个功能码）
• 02：非法数据地址（请求的寄存器地址超出范围）
• 03：非法数据值（写入的值不符合要求，比如写线圈时传了非 0xFF00 或 0x0000 的值）
7️⃣**写单个线圈的值规定**：对线圈的读写是对`数字量/开关量`的读写，其实就是`0和1`.协议规定，`0x0000`表示`OFF`是逻辑0，`0xFF00`表示`ON`是逻辑1，只有这两个值才能写入，其他值都是非法值，返回异常码`EX_ILLEGAL_VALUE`

```c
if (value != 0xFF00 && value != 0x0000)
{
    send_exception(FC_WRITE_COIL, EX_ILLEGAL_VALUE);
    return;
}
```

8️⃣**原式回显Echo:**

```c
// 写单个保持寄存器 - 把请求原样 echo 回去
send_response(rx_buf, rx_len);//对应功能码05

// 写单个线圈 - 把请求原样 echo 回去
send_response(rx_buf, rx_len);//对应功能码06
```

协议规定：对于写单个寄存器（0x06）和写单个线圈（0x05），从机的正常响应是把**主站的请求报文原封不动地发回去**。主站通过比对发出的请求和收到的响应是否一致，来判断写入是否成功。
🔟**读保持寄存器的报文响应字节数**：保持寄存器为uint16_t类型，所以在回应字节数的时候，字节数应该是请求报文请求的寄存器数量的两倍

```c
tx[2] = count * 2;  // 字节数 = 寄存器数量 × 2
```
协议规定：读保持寄存器（0x03）和读输入寄存器（0x04）的响应报文中，"字节数"这个字段必须是请求的寄存器数量的两倍，因为每个寄存器占 2 字节。

1️⃣1️⃣ **寄存器数据的高低位字节序（大端序）：**🥰其实就是**高位在前，低位在后**，在报文里面数据/地址信息：高位在前，低位在后
✅报文里面的crc校验码：低位在前，高位在后

```c
tx[3 + i*2]     = hold_reg[start+i] >> 8;    // 高位字节在前
tx[3 + i*2 + 1] = hold_reg[start+i] & 0xFF;  // 低位字节在后
```
协议规定：Modbus 协议对 16 位寄存器的传输顺序有明确规定：高字节在前，低字节在后（大端序/Big-Endian）。
比如寄存器值为 0x1234，发送顺序是 0x12 然后 0x34。


1️⃣2️⃣**CRC 的小端序编码**：见上面⬆️

```c
// 解析收到的 CRC
crc_rx = ((uint16_t)rx_buf[rx_len-1] << 8) | (rx_buf[rx_len-2]);

// 构造发送的 CRC
tx[tx_len]   = crc & 0xFF;   // 低字节在前
tx[tx_len+1] = crc >> 8;     // 高字节在后
```

协议规定：Modbus CRC-16 的校验值在报文中是低字节在前，高字节在后（Little-Endian）。

1️⃣3️⃣**从站地址过滤**：Modbus是挂载到总线上的，所以所有从机其实都能收到消息，但是在接受到数据的时候，先检验报文里面的从机地址，不是自己的视为垃圾数据，直接丢掉就行了，同时也闭嘴，不用发异常响应，不然会有噪音。

```c
if (addr != SLAVE_ID && addr != 0x00)
{
    return;  // 不是发给我的，也不是广播，直接丢弃
}
```
协议规定：每个从机都有自己唯一的地址（SLAVE_ID），只响应对应地址的请求和广播地址的请求。其他地址的报文一律忽略。

**😊协议规则小结表格**
| 协议规则 | 体现位置 |
| :--- | :--- |
| 3.5 字符帧间隔 | `FRAME_TIMEOUT = 4` |
| 最短帧长 4 字节 | `if (rx_len < 4)` |
| CRC 错误静默丢弃 | `if (crc_rx != crc_calc) return;` |
| 广播不响应异常 | `if (addr != 0x00) send_exception(...)` |
| 地址过滤 | `if (addr != SLAVE_ID && addr != 0x00) return;` |
| 4 种数据空间 | 4 个独立数组 |
| 异常响应功能码 | `0x80` |
| 异常码标准化 | `EX_ILLEGAL_FUNC` / `ADDR` / `VALUE` |
| 线圈写入值约束 | `0xFF00` / `0x0000` |
| 写操作原样回显 | `send_response(rx_buf, rx_len)` |
| 寄存器大端序 | `>>8` 在前，`& 0xFF` 在后 |
| CRC 小端序 | 低字节在前，高字节在后 |

## 🚨报文格式

```c
// ================================================================
// Modbus RTU 报文格式整理（主机请求 / 从机响应）
// ================================================================

/*
 *  通用帧结构（ADU）：
 *  [从站地址 1B][功能码 1B][数据区 NB][CRC低 1B][CRC高 1B]
 *  CRC 覆盖范围：从站地址 + 功能码 + 数据区
 *  CRC 字节序：低字节在前，高字节在后（小端序）
 */

// ================================================================
// 功能码 0x03 (FC_READ_HOLD) —— 读保持寄存器
// ================================================================
/*
 *  主机请求：
 *  [SLAVE_ID][0x03][起始地址H][起始地址L][数量H][数量L][CRC低][CRC高]
 * 
 *  从机正常响应：
 *  [SLAVE_ID][0x03][字节数(数量×2)][数据1H][数据1L]...[数据NH][数据NL][CRC低][CRC高]
 * 
 *  从机异常响应：
 *  [SLAVE_ID][0x83][异常码(02)][CRC低][CRC高]
 *  异常码 02 = EX_ILLEGAL_ADDR（地址越界或数量非法）
 */

// ================================================================
// 功能码 0x04 (FC_READ_INPUT) —— 读输入寄存器
// ================================================================
/*
 *  主机请求：
 *  [SLAVE_ID][0x04][起始地址H][起始地址L][数量H][数量L][CRC低][CRC高]
 *
 *  从机正常响应：
 *  [SLAVE_ID][0x04][字节数(数量×2)][数据1H][数据1L]...[数据NH][数据NL][CRC低][CRC高]
 *
 *  从机异常响应：
 *  [SLAVE_ID][0x84][异常码(02)][CRC低][CRC高]
 *  异常码 02 = EX_ILLEGAL_ADDR（地址越界或数量非法）
 *
 *  说明：格式和 0x03 完全相同，区别只在于数据取自 input_reg[] 而非 hold_reg[]
 */

// ================================================================
// 功能码 0x06 (FC_WRITE_HOLD) —— 写单个保持寄存器
// ================================================================
/*
 *  主机请求：
 *  [SLAVE_ID][0x06][寄存器地址H][寄存器地址L][写入值H][写入值L][CRC低][CRC高]
 *
 *  从机正常响应：
 *  [SLAVE_ID][0x06][寄存器地址H][寄存器地址L][写入值H][写入值L][CRC低][CRC高]
 *  （与主机请求完全一致，原样回显 Echo）
 *
 *  从机异常响应：
 *  [SLAVE_ID][0x86][异常码(02)][CRC低][CRC高]
 *  异常码 02 = EX_ILLEGAL_ADDR（寄存器地址越界）
 */

// ================================================================
// 功能码 0x05 (FC_WRITE_COIL) —— 写单个线圈
// ================================================================
/*
 *  主机请求：
 *  [SLAVE_ID][0x05][线圈地址H][线圈地址L][写入值H][写入值L][CRC低][CRC高]
 *  写入值：0xFF00 = ON（逻辑1），0x0000 = OFF（逻辑0），其他值均非法
 *
 *  从机正常响应：
 *  [SLAVE_ID][0x05][线圈地址H][线圈地址L][写入值H][写入值L][CRC低][CRC高]
 *  （与主机请求完全一致，原样回显 Echo）
 *
 *  从机异常响应（两种情况）：
 *  1. [SLAVE_ID][0x85][异常码(02)][CRC低][CRC高]  ← 线圈地址越界
 *     异常码 02 = EX_ILLEGAL_ADDR
 *
 *  2. [SLAVE_ID][0x85][异常码(03)][CRC低][CRC高]  ← 写入值非法
 *     异常码 03 = EX_ILLEGAL_VALUE
 *     （写入值既不是 0xFF00 也不是 0x0000）
 */

// ================================================================
// 未实现/不支持的功能码 —— 通用异常响应
// ================================================================
/*
 *  主机请求（以 0x01 为例）：
 *  [SLAVE_ID][0x01][...][CRC低][CRC高]
 *
 *  从机异常响应：
 *  [SLAVE_ID][0x81][异常码(01)][CRC低][CRC高]
 *  异常码 01 = EX_ILLEGAL_FUNC（不支持的功能码）
 *
 *  说明：
 *  - 如果从站地址是广播（0x00），则不产生任何响应（静默丢弃）
 *  - 异常响应功能码 = 请求功能码 | 0x80（最高位置1）
 */

// ================================================================
// CRC 校验说明
// ================================================================
/*
 *  多项式：0xA001（Modbus CRC-16 标准）
 *  初始值：0xFFFF
 *  字节序：小端序（低字节在前）
 *
 *  示例：01 03 00 00 00 01 → CRC = 0x840A → 报文：0A 84
 *
 *  校验范围：从站地址 + 功能码 + 数据区（不含 CRC 自身）
 *  CRC 错误处理：从机静默丢弃，不发送任何响应
 */
```

## 通信阶段

由`上位机`发送`命令/请求`，`传感器/从机`执行指令，从机`响应返回报文`

## 寄存器

**这里的读写属性都是针对stm32而言**

* 离散输入状态：`开关量` `数字输入` 类比`按键输入`，是**1bit的只读寄存器**
* 线圈状态：`开关量` `数字输出` 类比`点灯输出`，是**1bit的可读可写寄存器**
* 保持寄存器： `模拟量` `模拟输入` 类比`ADC采样`，是**16bit只读寄存器**
* 输入寄存器： `模拟量` `模拟输出` 类比`DAC输出`，是**16bit可读可写寄存器**

## 数据包内容

| 起始间隙 | 设备地址 | 功能码 | 数据 | CRC校验 | 停止间隙 |
| :---: | :---: | :---: | :---: | :---: | :---: |
| >=3.5个字符 | 8位 | 8位 | N*8位 | 16位 | >=3.5个字符 |

其中 **功能码**决定了`寄存器类别`和`读/写`操作
**数据部分**包含两部分：1.`reg_address`和`数据的value`
